# Support

## Where do I ask?

| I need to…                        | Go to                                                     |
| --------------------------------- | --------------------------------------------------------- |
| Understand the project            | [README](README.md) and [docs/FAQ.md](docs/FAQ.md)         |
| Understand the data               | [docs/data-dictionary.md](docs/data-dictionary.md)         |
| Understand the method             | [docs/methodology.md](docs/methodology.md)                 |
| Report a bug                      | [Bug report](../../issues/new?template=bug_report.yml)     |
| Report a wrong number             | [Data issue](../../issues/new?template=data_issue.yml)     |
| Propose a feature                 | [Feature request](../../issues/new?template=feature_request.yml) |
| Report a vulnerability            | [SECURITY.md](SECURITY.md) — never in public               |
| See what is missing               | [docs/CHECKLIST.md](docs/CHECKLIST.md)                     |

## Before asking

- Search issues and discussions; many questions were already answered.
- For bugs, include browser, device and steps to reproduce.
- For data issues, include the cell, year and month — without them it cannot be traced.
- Keep snippets short and remove anything private.

## Response times

The project is maintained by volunteers during and after a 36-hour hackathon. There is no SLA.
Issues are triaged by impact and availability; during the event, bugs that block the demo come
first.
